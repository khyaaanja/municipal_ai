# Why "Track Your Complaint" Might Not Be Working

## How Tracking Works

The complaint tracking feature lets anyone — without an account — check the status of a complaint by entering a reference ID like `BK-A3X9Z7`.

**Flow:**
1. User goes to `/complaint/track/` and enters a complaint ID
2. The `track_complaint` view (in `complaints/views.py`) looks up the complaint by `complaint_id` in the database
3. If found, redirects to the public status page at `/complaint/status/BK-XXXXX/`
4. If not found, shows an error: *"No complaint found with that ID"*

## 🐛 THE MAIN BUG: JS Auto-Formatter Truncates the ID

**This is the primary reason you cannot copy/paste or type the full complaint ID correctly.**

Complaint IDs are generated by the model as: `'BK-'` + 6 random alphanumeric characters = **9 characters total** (e.g. `BK-A3X9Z7`).

But the JavaScript on the track page **hard-caps the input at 8 characters**, silently cutting off the last character:

```javascript
input.addEventListener('input', () => {
  let v = input.value.toUpperCase().replace(/\s/g, '');
  if (v && !v.startsWith('BK-') && v.length <= 7)
    v = 'BK-' + v.replace(/^BK-?/, '');
  input.value = v.slice(0, 8);   // ← BUG: 8 < 9 (IDs are 9 chars)
});
```

### What happens when you try to paste `BK-A3X9Z7`:

| Step | What the code does | Result |
|---|---|---|
| 1 | User pastes `BK-A3X9Z7` (9 chars) into input | Input shows `BK-A3X9Z7` |
| 2 | `.toUpperCase()` → `"BK-A3X9Z7"` | No change (already uppercase) |
| 3 | `.replace(/\s/g, '')` → `"BK-A3X9Z7"` | No change (no spaces) |
| 4 | Check: `v.startsWith('BK-')` → `true` | **If block is skipped** |
| 5 | `v.slice(0, 8)` → **`"BK-A3X9Z"`** | ❌ Last character `7` is silently cut off |
| 6 | Database lookup with `BK-A3X9Z` | ❌ **No match found — "No complaint found" error** |

### What happens when you type character by character:

1. You type `B`, `K`, `-`, `A`, `3`, `X`, `9`, `Z` → input shows `BK-A3X9Z` (8 chars) ✓
2. You type `7` → now `v = "BK-A3X9Z7"` (9 chars) → `v.slice(0, 8)` → `"BK-A3X9Z"`
3. **The last character `7` disappears from the input field immediately as you type it!**
4. You might think you typed it correctly, but the JS silently deleted the 9th character

### The Fix

Change the slice limit from `8` to `9` so that 9-character IDs (BK- + 6 chars) are accepted:

```javascript
input.value = v.slice(0, 9);  // ← allows BK-XXXXXX (9 chars)
```

The HTML `maxlength="10"` is already fine for 9 chars.

## Other Common Reasons It Fails

### 1. User Doesn't Have a Valid Complaint ID Yet
- Tracking requires a **reference number** (e.g., `BK-A3X9Z7`) received after submitting a complaint
- If the user just submitted a complaint, they need to **check their email** — the confirmation email includes the ID
- Anonymous submitters get the ID displayed on the success screen, but if they didn't note it down or check email, they have no way to look it up without an account

### 2. The ID Was Typed Incorrectly or Doesn't Exist
- The database lookup is case-insensitive (`complaint_id__iexact`)
- If the user transposes a character, or the complaint was never actually saved (e.g., the submission failed due to rate limiting, network error, or validation), no match is found

### 3. There Is No Link to "Track Your Complaint" from the Homepage/Login Page
- The track page at `/complaint/track/` exists and works, but **if there's no prominent link or button** pointing users to it, they won't know where to go
- The confirmation email does include a track link: `https://bhaktapur.gov.np/complaint/status/{complaint_id}/` (direct to status, not the track page)
- But the track page itself (`/complaint/track/`) may not be accessible from the main navigation or homepage

### 4. Check the URL Routing
The complaint URLs are mounted at `/complaint/`:
```python
path('complaint/', include('complaints.urls')),
```

And the track URL is:
```python
path('track/', views.track_complaint, name='complaint_track'),
```

So the full URL is **`/complaint/track/`** — not `/track/` or `/complaints/track/`. The user must be at exactly the right URL.

### 5. Anonymous Users Have No Account History
- If the user submitted the complaint **anonymously** (without logging in), they **must** have saved either the complaint ID or the claim token (sent via email)
- Unlike logged-in users who can see all their complaints at `/complaint/my/`, anonymous users have **no way** to browse their complaints — they must enter the exact ID
- The system relies on a `claim_token` (UUID) to later link anonymous complaints to accounts. But if the user lost the claim token and the complaint ID, the data is effectively unrecoverable

## Quick Summary

| Issue | Why It Happens | Fix |
|---|---|---|
| 🐛 **JS cuts off last character** | `v.slice(0, 8)` caps at 8 chars but IDs are 9 chars (`BK-` + 6 digits) | **Change to `v.slice(0, 9)` in the JS** |
| No ID to enter | User didn't save it or check email | Check inbox for "Complaint Received" email |
| "No complaint found" | Wrong ID, **truncated ID**, or complaint never saved | Double-check the 6-character code after `BK-` |
| Can't find the track page | No navigation link | Go directly to `/complaint/track/` |
| No status for new complaint | Complaint is pending review | Wait for municipality to update status |
| Anonymous user lost ID | No account = no history | Need the claim token or complaint ID from submission email |
